# Froggion — главная страница

Статический сайт сервиса аренды AFK-ботов. В центре — 3D-остров на three.js: четыре бота повторяют
движения из записей Replay Mod. Всё остальное — обычный HTML, который собирается из текстов в `content/`.

## Быстрый старт

Нужен Node.js 22 LTS (подойдёт и 20.19+, но `npm run check` на Windows с Node 20 не найдёт тесты).

```sh
npm ci
npm run dev        # разработка: http://localhost:5173/ и /en/
npm run preview    # собрать и открыть готовый сайт: http://localhost:4173/
npm run check      # тесты, сборка и проверка веса страницы
```

Параметры адреса для проверки: `?night` / `?day` — вариант сцены, `?lite` — облегчённый режим как на телефоне,
`?still` — страница без анимации (как при «уменьшить движение»), `?motion` — с анимацией.

Если сцена не двигается, откройте консоль браузера: там написано почему. Обычно это выключенное
аппаратное ускорение (нет WebGL) — тогда остаются постер и список ботов.

## Где что лежит

| Что | Где |
| --- | --- |
| Все тексты страницы | `content/ru.json`, `content/en.json` |
| Адрес панели, контакты, домен, цены, вариант сцены | `site.config.json` |
| Исходники: реплеи, скины, скриншоты панели, логотип | `source/` |
| Какие боты на острове и их скины | `source/bots.json` |
| Готовые данные сцены (результат инструментов) | `public/data/` |
| Текстуры (свои, 16×16) | `public/textures/` |
| Постеры, кадры станций, превью для соцсетей | `public/poster*.webp`, `public/stations/`, `public/og*.jpg` |
| Код страницы и сцены | `src/` |
| Инструменты подготовки и тесты | `tools/` |

## Тексты

Тексты правятся только в `content/ru.json` и `content/en.json`. Ключи в обоих файлах должны совпадать:
`npm run check` сравнит их и сообщит, если чего-то не хватает. Весь текст попадает в готовый HTML при сборке.

- Имена и описания ботов для карточек — `bots.<ник>`.
- Блоки «Работа ботов» — `jobs.attack`, `jobs.fish`, `jobs.mine`, `jobs.farm`.
- Цены в тексты не пишутся: таблицы и калькулятор берут их из `site.config.json` → `pricing`.
  Там же скидки, апгрейды и сроки.
- Адрес панели (`panelUrl`), заявки партнёров (`partnersUrl`) и контакты — в `site.config.json`.
- Пока ссылка перечислена в `comingSoon`, все кнопки с ней ведут на страницу-заглушку `/soon/`
  («Упс, тут пока пусто»), тексты заглушки — `soon` в `content/*.json`. Когда, например, заработает панель,
  уберите `panelUrl` из списка — кнопки поведут на её адрес.

## Скины

1. Положите PNG в `source/skins/` (64×64) и укажите файл в `source/bots.json`.
2. `npm run data` — определит модель (обычная или тонкие руки), запишет её в `source/bots.json`
   и скопирует скины в `public/skins/` без изменений. Кнопка «Скачать скин» отдаёт этот же файл.
3. `npm run posters` — перерисовать постеры и кадры станций с новым скином.

## Текстуры

Каждая текстура — отдельный PNG в `public/textures/` (`block/`, `item/`, `entity/`, `particle/`,
`environment/`). Чтобы заменить текстуру работой художника, положите файл с тем же именем и тем же
размером — код менять не нужно.

- Обычные текстуры — 16×16. Анимированные (`block/water_still`, `block/water_flow`, `block/lava_still`,
  `block/lava_flow`) — вертикальная лента кадров 16×16, кадры идут 10 раз в секунду. `*_flow` — боковые
  грани жидкостей, как в игре.
- Цвета травы, листвы и воды уже в файлах, код их не подкрашивает.
- `entity/creeper.png` — развёртка модели 64×32.
- `npm run textures` рисует только недостающие файлы и не трогает замены. `npm run textures -- --force`
  перерисует все свои текстуры поверх замен.
- После замены: `npm run posters`, чтобы постер совпадал со сценой.

## Данные сцены из реплеев

```sh
npm run data                # скины + реплеи → public/data/*.json и отчёт reports/replays.md
npm run data:suggest-loops  # подсказать отрезки для бесшовного цикла каждого бота
```

- Какие реплеи и какую область мира брать — `source/scene.json`.
- Отрезки цикла для каждого бота — `source/loops.json` (реплей и тики начала и конца).
- Фонари и факелы ночного варианта — `source/night.json`: координаты мира и блок. Инструмент проверит,
  что место свободно и есть опора.

Сайт читает только готовые файлы из `public/data/`, их нужно коммитить.

## Вариант сцены и анимация

- `site.config.json` → `scene.variant`: `"night"` (по умолчанию) или `"day"`. Постеры и кадры станций есть
  для обоих вариантов. Сравнить можно без пересборки: `?night` и `?day` в адресе.
- `site.config.json` → `motion`: `"always"` (по умолчанию) — сцена, облёт, анимации и плавная прокрутка
  работают всегда; `"system"` — выключаются, если в системе включено «уменьшить движение».
- Плавная прокрутка включается только для колеса мыши; тачпад и касания прокручивают страницу как обычно.

## Постеры, кадры станций и превью

```sh
npm run posters
```

Собирает сайт, открывает его в headless Chromium и снимает кадры сцены: постеры первого экрана
(пока грузится three.js и когда 3D недоступно), кадры станций для блоков «Работа ботов» без 3D
и картинки для соцсетей `og.jpg` (русская) и `og-en.jpg`. Нужен Chromium от Playwright
(`npx playwright install chromium`) или путь к своему в переменной `CHROMIUM_PATH`.

`npm run screenshots` снимает страницу целиком в разных состояниях в папку `screenshots/`
(`NIGHT=1` — ночной вариант).

## Шрифт

Пиксельный текст набран шрифтом «Minecraft 1.1» (автор Pwnage_Block, лицензия
[CC BY-SA 3.0](https://creativecommons.org/licenses/by-sa/3.0/)): коммерческое использование разрешено при
указании автора и лицензии — строка об этом стоит в подвале сайта. Исходный файл — `source/fonts/`.

`npm run fonts` упаковывает его в `src/fonts/pixel.woff` (глифы и имена не меняются) и собирает
`src/fonts/pixel-extra.woff` — наши глифы в той же пиксельной сетке для знаков, которых в шрифте нет:
₽ — – − « » → × … · ©. Нарисованы в `tools/prepare-fonts.js` (таблица `GLYPHS`). Размеры пиксельного текста
на сайте кратны 8 px — так пиксели шрифта остаются квадратными. Лицензия и авторство — `src/fonts/LICENSE.txt`.

## Лавопады

Лава, которой нет в записях, задаётся в `source/decor.json` (координаты источников в мире). Конвертер
разливает её по правилам игры (`tools/lib/fluids.js`): падает, пока снизу пусто, и растекается в стороны на
два уровня за блок. Внизу потоки растворяются в пустоте, ночью светятся. После правки — `npm run data`.

## Производительность

- Сначала показывается постер, three.js и данные сцены грузятся после первой отрисовки.
- Анимация на паузе, когда остров не виден или вкладка скрыта. DPR не выше 2, на телефонах — 1.5 и 30 кадров в секунду.
- Без WebGL (или с `?still`) остаются постер, статичные кадры станций и список ботов для карточек.
- `npm run budget` (входит в `check`) считает, сколько скачивает главная без three.js и скинов, в gzip.
  Лимит — 300 КБ. Сейчас около 229 КБ со сценой и 235 КБ без неё.

## Сборка и выкладка

```sh
npm ci
npm run check      # или просто npm run build
```

Результат — папка `dist/`: `index.html`, `en/`, `offer/`, `privacy/`, `sitemap.xml`, `robots.txt`
и статика. Сайт рассчитан на корень домена `https://froggion.bot/`. Пример для nginx:

```nginx
server {
    listen 443 ssl http2;
    server_name froggion.bot;
    root /var/www/froggion/dist;

    gzip on;
    gzip_types text/css application/javascript application/json application/manifest+json image/svg+xml text/xml;

    location / {
        try_files $uri $uri/ =404;
        add_header Cache-Control "no-cache";
    }
    # Файлы с хешем в имени не меняются никогда.
    location /assets/ {
        add_header Cache-Control "public, max-age=31536000, immutable";
    }
    # Данные сцены, текстуры и скины запрашиваются с ?v=<сборка>, картинки меняются редко.
    location ~* \.(json|png|webp|jpg)$ {
        add_header Cache-Control "public, max-age=86400";
    }
}

server {
    listen 443 ssl http2;
    server_name www.froggion.bot;
    return 301 https://froggion.bot$request_uri;
}
```

Скопировать сборку на сервер: `rsync -av --delete dist/ user@server:/var/www/froggion/dist/`.

### GitHub Pages

Workflow `.github/workflows/deploy.yml` собирает и публикует сайт при пуше в `main` (или вручную:
Actions → Deploy to GitHub Pages → Run workflow). Один раз включите Pages: Settings → Pages → Source:
GitHub Actions.

Pages открывает сайт из подпапки `https://<аккаунт>.github.io/<репозиторий>/`, поэтому workflow передаёт
этот путь в `BASE_PATH`, а `vite.config.js` делает его базовым (`base`). Все ссылки, данные сцены, текстуры
и скины учитывают его сами. Проверить локально: `BASE_PATH=/Froggion-Homepage/ npm run preview` и открыть
http://localhost:4173/Froggion-Homepage/. Canonical и Open Graph по-прежнему указывают на https://froggion.bot.

## Ассеты

Ассетов Mojang в проекте нет: текстуры нарисованы своим скриптом (`tools/draw-textures.js`), модели ботов
и крипера построены в коде, скины — только из `source/skins/`.
