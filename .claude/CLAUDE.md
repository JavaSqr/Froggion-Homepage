# Froggion Homepage — контекст для продолжения работы

Главная страница сервиса аренды AFK-ботов Froggion. Исходное ТЗ целиком — `.claude/landing-prompt.md`
(читать при сомнениях, что и как задумано). Как пользоваться проектом — `README.md` (на русском, подробно).
Этот файл — выжимка облачной сессии: правила, текущее состояние, решения и грабли.

## Правила (из ТЗ, соблюдать всегда)

- Отвечать по-русски, коротко; в конце — краткий вывод: что получилось, что нет.
- Код и комментарии на английском, комментариев немного, в стиле окружающего кода.
- Работать в отдельной ветке и пушить её. **В `main` не мержить** без явного «да» пользователя
  (дважды он разрешал «вся ветка в main» — это fast-forward; каждое разрешение одноразовое).
- Коммиты короткие, без префиксов (`feat:` и т. п.) и **без `Co-Authored-By`**; автор — `geniusandiq@gmail.com`
  (в git: `Java <geniusandiq@gmail.com>`).
- Вопросы — только на остановках из «Порядка работы» ТЗ или если не хватает данных.
- Никаких ассетов Mojang: ни из клиента, ни из npm-пакетов вроде `minecraft-assets`, ни скинов из API Mojang.
- Скины ботов — только из `source/skins/`, на сайт копируются в `public/skins/` как есть (их же отдаёт
  кнопка «Скачать скин»).
- Все прочие текстуры свои, 16×16, каждая отдельным файлом в `public/textures/` — чтобы художник мог
  заменить их без правки кода (`npm run textures` рисует недостающие).
- Шрифты — только с лицензией, разрешающей коммерческое использование на сайте.
- Слово Minecraft и его логотип в бренде не использовать (дисклеймер в подвале — можно).
- Каламбуры с «КВА» (КВА-рц, аКВА-риум…) — только в русском тексте; в английском и будущих переводах —
  без игры слов, по смыслу.

## Команды

```sh
npm ci
npm run dev          # http://localhost:5173/ и /en/
npm run preview      # сборка + http://localhost:4173/
npm run check        # тесты + сборка + бюджет веса
npm run data         # скины + реплеи → public/data/*.json, отчёт reports/replays.md
npm run posters      # постеры, кадры станций, og-картинки (headless Chromium)
npm run screenshots  # скриншоты состояний в screenshots/ (NIGHT=1 — ночь); можно имена шотов аргументами
npm run textures     # свои текстуры 16×16 (только недостающие; --force — все)
npm run fonts        # упаковка пиксельного шрифта + свои глифы
BASE_PATH=/Froggion-Homepage/ npm run preview   # проверка сборки под подпапку, как на Pages
```

Параметры адреса: `?night` / `?day`, `?lite` (как телефон), `?still` (без анимации), `?motion`,
`?debug` (в `window.__froggion.scene` появляются world, rig, renderer, scene, camera, atmosphere, tags).

## Архитектура (кратко)

- Vite 8, multi-page. HTML генерируется в Node из `content/ru.json`, `content/en.json` и `site.config.json`:
  `src/page/render.js` (вызывается плагином `tools/vite-pages.js`). **render.js работает в Node — нельзя
  импортировать в него браузерные модули** (например, `src/ui/eco.js`).
- `site.config.json`: ссылки, контакты, цены (`pricing`), языки, `comingSoon` (ключи ссылок, которые пока
  ведут на заглушку `/soon/`), `motion: "always"` (анимации даже при «уменьшить движение»),
  `scene.variant: "night"` (дневной вариант сохранён, `?day`).
- `src/main.js` — вход: эко-режим, карточки ботов, запуск сцены (лениво, после первой отрисовки),
  облёт, калькулятор, чаты, плавное колесо, доводка к разделам, меню.
- `src/ui/`: `cards.js` (карточка бота), `flyover.js` (скролл → камера, `jump` к боту по «Подробнее»),
  `smooth-wheel.js` (плавность только для колеса мыши), `section-snap.js` (доводка), `eco.js` (эко-режим),
  `calculator.js` + `pricing.js` (цены), `chats.js` (появление сообщений).
- `src/scene/`: `index.js` (сборка сцены, цикл, API), `camera.js` (CameraRig: первый экран, станции,
  облёт), `world.js` (боты и сущности по лентам событий), `island.js` + `mesher.js` (меш острова),
  `atmosphere.js` (день/ночь, ореолы), `light.js` (запечённый свет), `lava.js`, `particles.js`,
  `nametags.js` (ники HTML-ом поверх canvas), `humanoid.js`, `creeper.js`, `items.js`, `timeline.js`.
- `tools/`: `replay-to-timeline.js` (реплеи → данные), `lib/fluids.js` (растекание лавы по правилам 1.16),
  `prepare-fonts.js`, `draw-textures.js`, `render-poster.js`, `screenshots.js`, `check-budget.js`, тесты в
  `tools/test/`.
- Данные: `source/scene.json` (реплеи и область), `source/loops.json` (циклы ботов), `source/night.json`
  (ночные фонари/факелы), `source/decor.json` (лавопады со стороны Шахтёра — дырка в каменной части острова
  и пара источников ниже). Результат — `public/data/*.json` (коммитится).
- Шрифт: «Minecraft 1.1» (Pwnage_Block, CC BY-SA 3.0) — `src/fonts/pixel.woff` + свои глифы
  `pixel-extra.woff` (₽ — – − « » → × … · ©); строка авторства в подвале обязательна.
  **Размеры пиксельного текста кратны 8 px**, иначе пиксели шрифта неровные.

## Ключевые решения и где их крутить

- Сцена в `.stage`: слой `.scene-layer` sticky поверх первого экрана и блоков «Работа ботов», уходит вместе
  с поднимающимся разделом «Надёжность и автоматизация». `.hero` с `pointer-events: none` (иначе не работает
  наведение на ботов).
- Облёт: на бота полтора экрана прокрутки (`body.scene-flight .job { min-height: 150vh }` в `main.css`),
  камера догоняет скролл с инерцией `FOLLOW = 4`, стоит на станции долю `HOLD = 0.2` (`camera.js`).
  Перелёт — дугой вокруг центра острова с подъёмом (иначе камера проходит сквозь дерево). «Подробнее» в
  карточке — прямой перелёт к боту (`jump`), а не через всех по очереди.
- Частота кадров (`index.js`): 30 к/с в покое, 60 пока камера движется (`rig.moving`), не выше 60 на
  мониторах 120–144 Гц; телефоны (`lite`) — 30. Цикл на паузе, когда остров не виден или вкладка скрыта.
- Эко-режим: кнопка «Эко» в шапке (≤400 px — внутри меню), класс `eco` на `<html>`, `localStorage`
  `froggion-eco`; скрипт в `<head>` (в `render.js`) применяет его до отрисовки. Сцена замирает
  (`scene.setEco`, `rig.still`) и рисует кадр только по `invalidate()` (скролл, наведение, ресайз);
  выключены плавное колесо, доводка, появление сообщений и все CSS-переходы.
- Доводка к разделам (`section-snap.js`): только начиная с «Возможностей», через 3 с (`IDLE`) после
  остановки; раздел, который влезает, — по центру; высокий — по ближнему краю; дальше половины экрана
  (`REACH`) не тянет; не трогает, если посетитель вводит/выделяет текст, открыто меню или низ страницы.
- Карточка бота (`cards.js`): встаёт над ботом, иначе справа/слева/снизу, никогда не поверх бота и его ника
  (`scene.bounds(nick)` — экранный прямоугольник бота с ником); сторона «липкая»; догоняет плавно (`FOLLOW 16`).
- Ночь: свет запечён в вершины (`light.js`), лунный свет с тенями, ореолы фонарей/факелов/лавы — все одним
  инстансным вызовом (`glowBatch` в `atmosphere.js`), без depth test, гаснут, если между камерой и светом
  блок (лучи по ячейкам, `occludes`).
- Ники над ботами — HTML (`nametags.js`), размер шагами 8 px (8–24), полупрозрачные за блоками.
- «Тарифы» упакованы под один экран ноутбука (подзаголовок + бейдж в строку, «Ботов» в строку со слайдером,
  «Итого» рядом с кнопкой): контент ~643 px. Окно пользователя, судя по скриншотам, ≈1470×778 CSS px
  (1920×1080 с масштабом Windows 125%) — ориентир для «влезает в экран».
- Шапка: компактная до 600 px (иначе на iPhone Pro Max 430 px кнопка меню уезжала за край), проверена
  на 320–1081 px без горизонтальной прокрутки.

## Грабли

- Время из `requestAnimationFrame` бывает меньше `performance.now()` момента старта — dt ограничивать снизу
  нулём (так сделано в сцене, карточках, плавном колесе).
- Headless Chromium в инструментах: `CHROMIUM_PATH`, иначе браузер Playwright; WebGL через SwiftShader
  (`--use-angle=swiftshader --enable-unsafe-swiftshader`). Он медленный — частоту кадров и нагрузку ЦП
  там не измерить, только логику.
- `vite preview` запускать как `node node_modules/vite/bin/vite.js preview` (через npx дочерний процесс
  не убивается и держит порт).
- Скриншоты блоков ботов: опция `center: true` в `tools/screenshots.js` (блок высотой 150vh, станция —
  по его центру).
- У `input[type=range]` минимальная ширина ~129 px — в строке с подписью ему нужен `width: 0`, иначе
  калькулятор распирает страницу на телефоне.
- Сетки на узких экранах — `minmax(0, 1fr)`, а не `1fr` (иначе переполнение по min-content).
- Ключ эко-режима `froggion-eco` записан в двух местах: `src/ui/eco.js` и скрипт в `<head>` в `render.js`.

## Открытые вопросы и идеи

- Снижение нагрузки проверено только логикой; на реальном железе пользователя замер не делался —
  спросить, сколько ЦП теперь.
- Ники на первом экране 8 px (как в игре при мелком масштабе); предлагал поднять до 16 px — ответа не было.
- «Возможности» (~737 px) на экране 1470×778 чуть выше экрана — доводка выравнивает по краю; просили
  уместить только «Тарифы».
- Первое появление новых объектов (крипер, предметы) компилирует шейдеры — возможны короткие подтормаживания;
  можно прогреть через `renderer.compileAsync`.
- Постеры и кадры станций после последнего раунда не перерисовывались (визуально не менялись).
